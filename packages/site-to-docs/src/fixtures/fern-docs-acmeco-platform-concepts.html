Overview

Key Concepts

Resources that will help you get started using the Plant Store API

This page demonstrates various markdown features while explaining the core concepts of the Plant Store API. You’ll find bold italic text, inline code, and more!

Plant Resource

A plant can be bought from the store. It has a name, category, tags (array), and a status.

Plant Attributes

FieldTypeDescription
namestringThe common name of the plant
categorystringThe type of plant (e.g., “Indoor”)
tagsarrayArray of tags (e.g., ["green", "leafy"])
statusstringAvailability status

Plant Status Values

The plant status can be one of:

  1. available - Currently in stock
  2. pending - Awaiting processing
  3. sold - No longer available

Example Plant Object

1{
2  "id": 101,
3  "name": "Fern",
4  "category": "Indoor",
5  "status": "available",
6  "tags": ["green", "leafy"]
7}

Plant API Endpoints

MethodEndpointDescription
GET/plant/{plantId}Get plant by ID
POST/plantAdd a new plant
PUT/plantUpdate an existing plant
GET/plant/search/statusSearch plants by status
GET/plant/search/tagsSearch plants by tags

Store Resource

A store manages plant inventory and processes orders. The store tag provides access to Plantstore orders.

Note: Store operations are managed through the plant and user endpoints.

User Resource

A user is a person who buys plants from the store. Also known as plant parents.

User Profile Fields

FieldTypeDescription
idintegerUnique user identifier
usernamestringUser’s username
emailstringUser’s email address

User API Endpoints

MethodEndpointDescription
GET/user/{username}Get user by username
GET/user/auth/loginLog user into the system
GET/user/auth/logoutLog out current session
